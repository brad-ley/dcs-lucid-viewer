Lucid Camera Acquisition Tool

User Manual — Live Preview and High-Speed Image Acquisition

For ATX245S hardware specifications, GPIO wiring, and firmware details, see the ATX245S Camera Manual ↗

ATX245S sensor: pixel pitch = 2.74 µm/pixel (Sony IMX547, 24.5 MP, 5328 × 4608 active pixels). Use this value when converting pixel distances to physical units (e.g., for FOV or spatial-frequency calculations).

Overview

The Lucid Camera Acquisition Tool is a desktop application for controlling Lucid Vision Labs cameras and acquiring high-quality images. It provides both live preview and batch acquisition modes, with extensive parameter customization and automated metadata logging.

This tool is built on Qt 6 with the Arena SDK, providing a responsive graphical interface for camera control and a robust backend for image processing and storage.

Key Features

  • Live Preview: Real-time camera stream with zoom/pan, auto-contrast display, and a live histogram
  • Continuous Acquisition: Captures frames to disk until stopped; automatic session folder naming with live placeholder preview
  • Auto-Stop: Configure a timed duration (µs/ms/s) so acquisition stops automatically with a live countdown on the Stop button
  • Pinned Parameters: Star any GenICam node in the Advanced dialog to keep it on the main panel; set persists in the registry
  • Advanced Parameter Browser: Full GenICam node tree with visibility filtering and per-node ★ pinning
  • Config Menu: Dialogs for auto-contrast percentile thresholds and auto-stop duration; all settings saved to the registry
  • Metadata Logging: Camera settings and per-frame gain stored in metadata.json and frame_data.csv; full save path printed to the log on completion
  • Save Formats: Raw sequence, TIFF sequence, or single Raw video file
  • Acquisition Notes: Free-form text saved alongside each acquisition session

Camera Connection

Connecting Your Camera

  1. Click the Camera Connection section to expand it
  2. A dropdown list shows all detected cameras connected to your system
  3. Select a camera from the list
  4. Click the Connect button to establish a connection
  5. If successful, the status will update and parameter controls will become available
Note: Only one camera can be connected at a time in this version. If you need to switch cameras, click Disconnect first.

Disconnecting

Click the Disconnect button to close the camera connection. This will stop any running preview or acquisition. The connection is also automatically closed when you exit the application.

Warning: Always disconnect or close the application properly. Abruptly terminating the process without properly releasing the camera device may require a system restart to reconnect.

Camera Parameters

The Camera Parameters section displays adjustable settings loaded from your camera's configuration. These parameters are dynamically built when you connect a camera and control image acquisition properties like exposure, gain, and image format.

Parameter Types

Type Description Example
Enumeration Fixed set of choices (displayed as combo box) AcquisitionMode: Continuous, SingleFrame, MultiFrame
Float Decimal number with range and precision (spinner control) ExposureTime: 50.0–1000000.0 microseconds
Integer Whole number with range (spinner control) Width: 640–4096 pixels
Boolean On/Off toggle (displayed as combo box) GainAuto: Off, Once, Continuous

Auto-Coupling

Some parameters are automatically coupled. For example, enabling ExposureAuto automatically disables the ExposureTime control (since the camera is controlling exposure automatically). Similarly, enabling GainAuto disables the Gain control.

These dependencies are automatically managed by the application — you don't need to manually disable/enable linked controls.

Applying Parameters

After adjusting parameters:

  1. Review your selected values
  2. Click the Apply button to send them to the camera
  3. A confirmation message appears in the log if successful
Tip: Click Refresh at any time to reload all parameter values from the camera. This is useful if the camera was modified by another application or if you want to discard unsaved changes.

Advanced Parameters

The Advanced button opens a separate dialog for camera-specific settings that are not included in the standard parameter set. These include low-level control options that expert users may need to fine-tune.

Accessing Advanced Settings

  1. Connect a camera first
  2. Click the Advanced button below the parameter controls
  3. A new window opens showing additional camera settings
  4. Adjust as needed and click OK to apply or Cancel to discard changes
Note: Advanced parameters vary by camera model. Not all cameras expose the same advanced settings. If you're unsure about a setting's purpose, consult your camera's technical documentation.
Live read-back: Each time you select a feature in the Feature dropdown, the dialog re-reads that node's current value directly from the camera — it never displays a stale cached value. This means dependent nodes update automatically after a related write (for example, TriggerSelector reflects the correct value after you change TriggerSource).

Config Menu

The Config menu in the main window menu bar controls acquisition preferences. All settings are saved to the Windows registry and restored automatically on the next launch.

Auto-Stop Acquisition

The Config menu contains two Auto-Stop items:

  • Auto-Stop Acquisition (checkable) — toggles the feature on or off directly from the menu. The check state persists across launches, so you can confirm at a glance whether timed stopping is armed before connecting a camera.
  • Auto-Stop Settings… — opens the settings dialog to configure the duration and unit.
Setting dialog control Description
Duration spinner Numeric duration value (up to 24 hours maximum)
Unit selector µs, ms, or s — switching units converts the displayed value so the physical duration stays the same

The Stop button reflects the auto-stop configuration immediately at application launch — if auto-stop was enabled in the previous session, the button already shows Stop (auto Ns) before a camera is even connected, so you can confirm the feature is armed at a glance.

When auto-stop is enabled and you click Start Acquisition, the Stop button immediately changes to show the remaining seconds (e.g., Stop (auto 10s)) and counts down each second. Hovering the button shows a tooltip with the exact remaining time. The acquisition stops cleanly when the timer fires — the same code path as a manual stop, so no frames are lost. Clicking Stop manually before the timer fires also cancels the countdown.

Note: The duration must be at least 1 ms. Sub-second durations (e.g., 500 µs) are valid but the Stop button countdown will show "1s" briefly before stopping.
Tip: Auto-contrast settings have moved to the Preview window's Auto-contrast menu — see Live Preview.

Acquisition

The Acquisition section controls high-speed frame capture. Use this to acquire a batch of frames and save them to disk along with metadata.

Setting Up Acquisition

  1. Connect a camera and configure parameters (Exposure, Gain, etc.)
  2. Select a Save format:
    • Raw Sequence — one .raw file per frame (fastest)
    • TIFF Sequence — one .tiff per frame (readable in most image viewers)
    • Raw Video — single file with all frames concatenated
  3. Optionally enter an Acq. name (custom folder name). The placeholder text shows the auto-generated name that would be used if left blank (e.g., acq_20260604_143022). If the folder already exists, a numeric suffix is appended (_2, _3, …).
  4. Click Notes... to attach free-form notes saved in metadata.json
  5. Choose an Output folder with Browse
  6. Optionally configure a timed stop via Config → Auto-Stop Acquisition

Starting and Stopping Acquisition

Click Start Acquisition to begin. If TriggerMode is set to On, the button label changes to Start Streaming instead — this indicates that the camera will wait for a hardware trigger signal to deliver frames rather than starting immediately in software. The Stop button and auto-stop timer behave identically in both cases.

Frames are captured and saved continuously until you click Stop Acquisition or the auto-stop timer fires. The frame counter and live FPS are updated in real time. When acquisition finishes:

  • Start Acquisition becomes enabled again
  • The log prints the total frame count and the full path to the saved folder, e.g., Acquisition finished — 200 frames saved to: 'C:/LucidCaptures/acq_20260604_143022'
  • The session name placeholder refreshes to the current timestamp, ready for the next run
Warning: The preview window is automatically paused during acquisition to prevent contention for the camera device. It resumes automatically when acquisition completes.

Auto-Stop

See Config Menu → Auto-Stop Acquisition for setup details. When enabled, the Stop button displays a live countdown:

  • Stop (auto 10s) → Stop (auto 9s) → … → acquisition stops
  • Clicking Stop manually at any time also cancels the countdown cleanly
  • The button turns orange during the countdown to distinguish it from a manual stop

Output Files

Each acquisition creates a subfolder in the chosen output directory containing:

File Contents
frame_0000.raw / .tiff Individual frame files (one per frame in sequence formats)
acquisition.raw All frames concatenated (Raw Video format only)
metadata.json Acquisition timestamp, camera settings snapshot, notes
frame_data.csv Per-frame index, timestamp (ns since start), and gain (dB)
camera_settings.json Full snapshot of every readable camera node at acquisition start — equivalent to Save Custom in the Advanced dialog. Useful for exactly reproducing camera state in a future session.

Live Preview

The Preview button opens a modeless preview window — the main window stays fully interactive while preview is open. Use it for focusing, composing shots, drawing ROI regions, and verifying camera settings before acquisition.

Starting and Stopping

  1. Connect a camera
  2. Click the Preview button in the Acquisition section
  3. In the preview window, click Start Preview to begin streaming
  4. Adjust camera parameters on the main window and click Apply Pinned Parameters to see the changes live
  5. Click Stop Preview to stop, or close the window directly — streaming stops automatically
Note: Preview is automatically paused when you start acquisition — both cannot use the camera simultaneously. It resumes automatically when acquisition completes.

Image Display

The main image area supports interactive navigation:

  • Scroll wheel — zoom in/out centred on the cursor position
  • Drag — pan a zoomed image
  • Double-click — fit the image to the window
  • Right-click — pin a pixel readback overlay showing the raw sensor count at the clicked position; updated automatically on each new frame

Two colour overlays assist with exposure tuning:

  • Red tint — pixels that are fully saturated (value = 255 in the 8-bit display range)
  • Yellow tint — pixels that are always zero (potentially dead pixels or underexposed regions)

Histogram

A live histogram widget appears to the right of the image. It shows the pixel intensity distribution of the current frame and includes two draggable handles for the black point (left) and white point (right). Dragging a handle immediately remaps the display range without waiting for the next frame from the camera.

Auto Contrast

Auto contrast automatically computes percentile-based black and white points each frame and applies them to the histogram handles. It can be toggled two equivalent ways:

  • Auto Contrast button in the bottom bar — white when off, turns blue when on
  • Auto-contrast → Enable Auto Contrast in the menu bar (checkable)

To change the percentile thresholds, use Auto-contrast → Auto Contrast Settings….

Setting Default Meaning
Low percentile 3.0 % Pixels below this intensity are clipped to black
High percentile 97.0 % Pixels above this intensity are clipped to white
Tip: A value of 0 % / 100 % is a full-range stretch with no clipping. Lower the low percentile or raise the high percentile for scenes with large uniform dark or bright regions.

Draw ROI

The Draw ROI button lets you define a region of interest by drawing a rectangle directly on the live image. It can be toggled two equivalent ways:

  • Draw ROI button in the bottom bar — white when off, turns orange when on; button label changes to Cancel ROI while drawing is active
  • ROI → Draw ROI Bounds in the menu bar (checkable)

When Draw ROI is active, click and drag on the image to draw a rectangle. On mouse release the ROI is applied: the four nodes (OffsetX, OffsetY, Width, Height) are automatically pinned to the main panel if they are not already there, and their values are populated with the drawn coordinates. A green overlay rectangle remains on the image to show the active ROI region.

To reset the ROI back to the full sensor area:

  • Right-click the Draw ROI button and choose Reset ROI to Full Frame
  • Or use ROI → Reset ROI to Full Frame in the menu bar

Focus Diagnostic

Tools → Open Focus Diagnostic opens the Focus Diagnostic dialog. It provides quantitative focus metrics on a sub-region of the image, useful for manual focus adjustment. If a ROI has been drawn, the diagnostic operates on that region; otherwise it samples the full frame.

FPS Counters and Status

The status bar at the bottom of the preview window shows:

  • Display FPS — how fast the preview is rendering (throttled to ~30 fps)
  • Camera FPS — the true acquisition rate reported by the camera
  • Line status — GPIO line states (from ChunkLineStatusAll bitmask) when chunk data is enabled; shows N/A if chunk data is not available

Output Files and Formats

Every acquisition session creates a timestamped folder inside your chosen output directory. The files written depend on the Save format selected before acquisition starts. The following files and formats are possible.

TIFF Stack (stack.tiff)

When TIFF Stack is selected, all acquired frames are written into a single multi-page TIFF file named stack.tiff. Each page is one frame, stored in the camera's native bit depth (typically 16-bit grayscale). No compression is applied.

Tip: Multi-page TIFFs can be opened in ImageJ/Fiji, MATLAB (imread with a frame index), Python's tifffile library, or most scientific image viewers. For large frame counts the file can be several gigabytes — make sure you have sufficient disk space before starting.

Raw Sequence (frame_000001.raw, frame_000002.raw, …)

When Raw Sequence is selected, each frame is saved as an individual binary file with a six-digit zero-padded frame number. The file contains only the raw pixel bytes from the camera — no header, no compression.

To load a raw frame you must know the image dimensions and pixel format from metadata.json. Example in Python:

import numpy as np, json with open("metadata.json") as f: meta = json.load(f) width = meta["width"] height = meta["height"] bpp = meta["bits_per_pixel"] # e.g. 16 dtype = np.uint16 if bpp > 8 else np.uint8 frame = np.fromfile("frame_000001.raw", dtype=dtype).reshape(height, width)
Packed formats (Mono12p, Mono12Packed, Mono10p, Mono10Packed): Raw files contain the camera's native packed bytes. Loading them as np.uint16 will give wrong values. Check pixel_format in metadata.json first — if it contains "Packed" or ends in "p", use the unpacking code in the Loading Image Data section below.

Raw Video (recording.raw)

When Raw Video is selected, all frames are concatenated into a single binary file named recording.raw. There are no frame delimiters or headers — the file is simply frame 0 followed immediately by frame 1, and so on. Each frame occupies exactly bytes_per_frame bytes (reported in metadata.json for all formats including packed ones).

This format has the lowest per-frame overhead and is suitable for high-speed acquisitions where individual file creation would be a bottleneck. To extract frames in Python:

import numpy as np, json with open("metadata.json") as f: meta = json.load(f) width, height = meta["width"], meta["height"] bpp = meta["bits_per_pixel"] frame_count = meta["frame_count"] bytes_per_frame = meta["bytes_per_frame"] # For non-packed formats (Mono8, Mono12, Mono16) — simple reshape dtype = np.uint8 if bpp == 8 else np.uint16 data = np.fromfile("recording.raw", dtype=dtype) frames = data.reshape(frame_count, height, width) # For packed formats (Mono12p, Mono12Packed, etc.) — extract by byte offset raw = np.fromfile("recording.raw", dtype=np.uint8) for i in range(frame_count): frame_bytes = raw[i * bytes_per_frame : (i + 1) * bytes_per_frame] # then apply the same unpacking code shown in the section above

Metadata File (metadata.json)

Written at the end of every acquisition regardless of format. Contains the information needed to interpret raw pixel files and to reproduce the acquisition conditions:

  • acquisition_time: ISO 8601 timestamp when the acquisition started
  • frame_count: Total frames acquired
  • width, height: Frame dimensions in pixels
  • bits_per_pixel: Camera's native bits per pixel (e.g. 12 for Mono12p)
  • pixel_format: Camera pixel format string (e.g. Mono12p)
  • bytes_per_frame: Exact byte size of one raw frame — correct for packed formats too; use this to seek to a specific frame in recording.raw
  • save_format: Which format was used (raw_sequence, tiff_stack, or raw_video)
  • notes: Your acquisition notes (if provided)
{ "session": "acq_20260603_143022", "acquisition_time": "2026-06-03T14:30:22", "notes": "Outdoor test, bright sunlight", "save_format": "raw_sequence", "width": 2448, "height": 2048, "pixel_format": "Mono12p", "bits_per_pixel": 12, "bytes_per_frame": 7520256, "frame_count": 100, "complete": true }
Tip: Notes entered via the Notes... button are embedded directly inside metadata.json under the "notes" key — no separate text file is created.

Camera Settings File (camera_settings.json)

A full snapshot of every readable GenICam node on the camera at the moment acquisition begins. This includes parameters you may not have pinned or adjusted — gain, exposure, trigger mode, line debounce values, chunk settings, and so on. It is equivalent to using Save Custom… in the Advanced Parameters dialog but is captured automatically for every session.

Use camera_settings.json to reproduce the exact camera state in a later session by loading it via Load Custom… in the Advanced Parameters dialog, or as a reference when debugging unexpected image behaviour.

Note: If the camera node map snapshot fails (rare — usually a timing issue at startup), the file may be absent or empty. The acquisition itself is not affected.

Frame Data File (frame_data.csv)

A comma-separated file with one row per acquired frame. Columns are always written in this order:

  • frame_index: Frame number (0-based)
  • timestamp_ns: Camera hardware timestamp in nanoseconds from an internal counter — use differences between rows to compute exact inter-frame intervals
  • gain_db: Gain embedded in the frame by the camera (dB, 4 decimal places); useful when auto-gain is active
  • exposure_us: Exposure time embedded in the frame by the camera (µs, 2 decimal places); useful when auto-exposure is active
  • line_status_all (optional): ChunkLineStatusAll bitmask — bit N is the state of GPIO Line N at the moment this frame was captured. This column is only present when chunk data is enabled via the Advanced Parameters dialog.
frame_index,timestamp_ns,gain_db,exposure_us,line_status_all 0,1234567890,6.5000,500.00,3 1,2468135780,6.5000,500.00,1 2,3701703670,6.5000,500.00,0

The gain_db and exposure_us values come from chunk data embedded in each image by the camera, so they reflect the setting that was actually active for that specific frame — not the value shown in the GUI at that instant. When auto-gain or auto-exposure is disabled these columns will be constant.

Loading Image Data into Python or MATLAB

The camera saves pixel intensities as numbers. Bit depth determines how many distinct intensity levels are available: 8-bit gives 256 levels (0–255), 12-bit gives 4096 levels (0–4095), and 16-bit gives 65,536 levels (0–65535). Higher bit depth means finer discrimination between brightness values — important for quantitative science.

To know which format your data is in, open metadata.json from your acquisition folder and check "pixel_format" and "bits_per_pixel".

TIFF Files — Easiest to Use

stack.tiff, white_field_mean.tiff, and dark_field_mean.tiff are standard multi-page TIFF files that most scientific software understands directly.

# Python — works for any bit depth import tifffile import numpy as np stack = tifffile.imread("stack.tiff") # shape: (frames, height, width) frame0 = stack[0] # first frame as a 2-D array print(stack.dtype) # uint8 (8-bit) or uint16 (12- or 16-bit) print(stack.shape) # e.g., (100, 4608, 5328)
% MATLAB stack = imread('stack.tiff', 1); % reads first page (frame 0) % To read all pages: info = imfinfo('stack.tiff'); stack = zeros(info(1).Height, info(1).Width, numel(info), 'uint16'); for k = 1:numel(info) stack(:,:,k) = imread('stack.tiff', k); end
Recommendation: Use TIFF Stack as your save format unless you need maximum write speed. TIFF files open directly in ImageJ/Fiji, MATLAB, and Python with no bit-unpacking needed.

Raw Files — Simple Formats (Mono8, Mono12, Mono16)

Raw files contain plain binary pixel values with no header. For uncompressed formats (anything where pixel_format does not contain "Packed" and does not end in lowercase "p"), loading is straightforward: each pixel occupies either 1 byte (8-bit) or 2 bytes (10-, 12-, or 16-bit).

import numpy as np, json with open("metadata.json") as f: meta = json.load(f) width = meta["width"] height = meta["height"] bpp = meta["bits_per_pixel"] # 8, 12, or 16 # uint8 for 8-bit cameras; uint16 for anything higher dtype = np.uint8 if bpp == 8 else np.uint16 frame = np.fromfile("frame_000001.raw", dtype=dtype).reshape(height, width) # 12-bit values occupy the lower 12 bits of each uint16 word. # All values are already in the correct 0–4095 range — no masking needed in practice. print(frame.max()) # should be ≤ 4095 for Mono12, ≤ 65535 for Mono16
% MATLAB fid = fopen('frame_000001.raw', 'rb'); frame = fread(fid, [width height], 'uint16=>uint16')'; % transpose: fread fills columns first fclose(fid); % For Mono8, use 'uint8=>uint8' instead

Raw Files — Packed Formats (Mono12p, Mono12Packed, Mono10p, Mono10Packed)

Packed formats store more than one pixel per byte to reduce file size. They require a decoding step before you can use the values. Check "pixel_format" in metadata.json — if it ends in "p" or contains "Packed", use the code below.

Mono12p (the most common 12-bit packed format on this camera) packs two 12-bit pixels into three consecutive bytes. The lower pixel fills the low bits of byte 0 and the low nibble of byte 1; the upper pixel fills the high nibble of byte 1 and all of byte 2.

import numpy as np, json with open("metadata.json") as f: meta = json.load(f) width = meta["width"] height = meta["height"] fmt = meta["pixel_format"] raw = np.fromfile("frame_000001.raw", dtype=np.uint8) if fmt == "Mono12p": # 3 bytes encode 2 pixels: [b0, b1, b2] → [p0, p1] # p0 = b0 | ((b1 & 0x0F) << 8) values 0–4095 # p1 = (b1 >> 4) | (b2 << 4) values 0–4095 b = raw.reshape(-1, 3) p0 = b[:, 0].astype(np.uint16) | ((b[:, 1].astype(np.uint16) & 0x0F) << 8) p1 = (b[:, 1].astype(np.uint16) >> 4) | (b[:, 2].astype(np.uint16) << 4) frame = np.empty(height * width, dtype=np.uint16) frame[0::2] = p0 frame[1::2] = p1 frame = frame.reshape(height, width) elif fmt == "Mono12Packed": # Same 3-bytes-per-2-pixels layout but with the nibble order swapped. # p0 = (b0 << 4) | (b1 & 0x0F) # p1 = (b2 << 4) | (b1 >> 4) b = raw.reshape(-1, 3) p0 = (b[:, 0].astype(np.uint16) << 4) | (b[:, 1].astype(np.uint16) & 0x0F) p1 = (b[:, 2].astype(np.uint16) << 4) | (b[:, 1].astype(np.uint16) >> 4) frame = np.empty(height * width, dtype=np.uint16) frame[0::2] = p0 frame[1::2] = p1 frame = frame.reshape(height, width)
Not sure which format you have? Check metadata.json → "pixel_format". The ATX245S most commonly uses Mono12p for 12-bit capture.

Loading the Full Raw Video (recording.raw)

Raw Video mode concatenates all frames with no delimiters. Each frame is exactly bytes_per_frame bytes long — read directly from metadata.json, which now reports the correct value for packed formats too.

import numpy as np, json with open("metadata.json") as f: meta = json.load(f) width = meta["width"] height = meta["height"] bpp = meta["bits_per_pixel"] frame_count = meta["frame_count"] bytes_per_frame = meta["bytes_per_frame"] fmt = meta["pixel_format"] # Non-packed formats (Mono8, Mono12, Mono16) — simple reshape if fmt not in ("Mono12p", "Mono12Packed", "Mono10p", "Mono10Packed"): dtype = np.uint8 if bpp == 8 else np.uint16 all_frames = np.fromfile("recording.raw", dtype=dtype) all_frames = all_frames.reshape(frame_count, height, width) else: # Packed formats — slice bytes_per_frame bytes per frame, then unpack each raw = np.fromfile("recording.raw", dtype=np.uint8) all_frames = [] for i in range(frame_count): frame_bytes = raw[i * bytes_per_frame : (i + 1) * bytes_per_frame] all_frames.append(frame_bytes) # unpack with code from section above

Applying Dark and White Field Correction

If you captured dark and white fields, correct your data frames with:

import tifffile, numpy as np dark = tifffile.imread("dark_field_mean.tiff").astype(np.float32) white = tifffile.imread("white_field_mean.tiff").astype(np.float32) frame = tifffile.imread("stack.tiff")[0].astype(np.float32) # first frame # Standard flat-field correction — result is 0.0 (dark) to 1.0 (white) denom = white - dark denom[denom == 0] = 1 # avoid divide-by-zero on dead pixels corrected = (frame - dark) / denom corrected = np.clip(corrected, 0.0, 1.0)

Understanding Metadata and Frame Data

Why Frame Data is Important

Modern cameras can vary their gain and exposure on a per-frame basis — particularly when auto-exposure or auto-gain is active. The values visible in the GUI are set-points, not readbacks; the camera may silently adjust them frame by frame. The frame_data.csv file records the values that were actually embedded in each frame by the camera's chunk data system, so you always have a precise per-frame record regardless of what the GUI showed. This lets you:

  • Correlate brightness variations to gain or exposure changes
  • Detect frames where auto-exposure has not yet settled
  • Synchronize timestamps with external sensors or events
  • Log GPIO line states alongside each frame when chunk data is enabled

Timestamps

Timestamps come from the camera's internal hardware counter and are recorded in nanoseconds. They are not wall-clock time — they are relative to an arbitrary camera epoch and are only meaningful as differences between rows. To compute frame intervals and detect dropped frames:

import pandas as pd df = pd.read_csv("frame_data.csv") df["interval_ms"] = df["timestamp_ns"].diff() / 1_000_000 # Flag frames where the interval is more than 10 % above the expected period expected_ms = 1000 / 30 # e.g. 30 fps df["dropped"] = df["interval_ms"] > expected_ms * 1.10 print(df[df["dropped"]])

Chunk Data Dependency

The gain_db, exposure_us, and line_status_all columns all come from chunk data embedded in each frame by the camera. Chunk data must be enabled in the Advanced Parameters dialog before streaming — see the ChunkModeActive and ChunkEnable nodes. If chunk data is not enabled those columns will contain placeholder values or be absent, and the live GPIO display in the preview window will show N/A.

Tips and Troubleshooting

Camera Not Detected

Problem: The camera dropdown is empty or doesn't show your camera.

Solutions:

  • Verify the camera is powered and connected to your computer via Ethernet (for GigE cameras)
  • Check Windows Device Manager to confirm the network adapter is working
  • Restart the application
  • If using a 10GigE camera, verify your NIC supports jumbo frames (8192 bytes)
  • Consult the Arena SDK documentation for your specific camera model

Preview Displays Blank or Corrupted Images

Problem: Preview window shows no image or garbled pixels.

Solutions:

  • Ensure your lighting is adequate — very dark scenes may appear black
  • Check exposure and gain settings; they may be too low
  • Click Refresh to reload parameter values from the camera
  • Stop and restart preview by clicking Stop Preview, then Start Preview again
  • If the issue persists, disconnect and reconnect the camera

Acquisition Stops Unexpectedly

Problem: Acquisition halts mid-way or produces incomplete results.

Solutions:

  • Check the log window for error messages that indicate the root cause
  • Ensure your output directory is not on a slow/unreliable drive
  • For GigE cameras, verify network stability and packet loss
  • Reduce frame count and try again
  • Check that your disk has sufficient free space

Parameters Don't Apply or Show Errors

Problem: "Apply" button shows an error or parameters revert to previous values.

Solutions:

  • Some parameters depend on others (e.g., can't set ExposureTime if ExposureAuto is on)
  • Check that your value is within the valid range for that parameter
  • Click Refresh to see the camera's current values
  • Some parameters may be read-only on your camera — consult the camera manual

High CPU Usage or Frame Drops

Problem: Preview FPS drops below 30, or the application lags.

Solutions:

  • Close other resource-heavy applications
  • For high-resolution cameras, the image scaling in preview may be slow — this is normal for very large images
  • On laptops, ensure the power plan is set to "High Performance" in Windows Settings
  • If using remote acquisition over a network, latency may limit frame rate — this is expected
