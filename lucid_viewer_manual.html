LucidLabs ATX245 Viewer User Manual

A standalone image viewer for Lucid Vision Labs ATX245 mono-camera data — supports .raw, .tiff, and .mp4/.avi files with automatic sidecar metadata loading.

Overview

The ATX245 Viewer is a PyQt6 / pyqtgraph application designed for reviewing raw image data captured by Lucid Vision Labs cameras (and compatible GenICam-standard devices). Key features:

  • Lazy frame loading — only the current frame is held in memory (plus a small LRU cache)
  • Automatic pixel-format detection from filename or JSON sidecar
  • Timestamp overlay from an adjacent timestamps.csv
  • Adjustable colormaps, auto-levels, and pyqtgraph histogram
  • Persistent window geometry and last-used settings

Opening Files

Use File → Open file… (Ctrl+O) or the Open image file… button in the sidebar to browse for a file. Supported extensions:

ExtensionFormatNotes
.rawBinary pixel data Set Width, Height, and Pixel format before opening. Frame count is inferred automatically from file size.
.tiff / .tif TIFF (single or multi-frame) Width/Height/format are read from TIFF metadata; sidebar values are ignored.
.mp4 / .aviVideo Frames are decoded via OpenCV. Grayscale conversion is applied automatically.

Frame Format Panel (sidebar)

For .raw files you must configure the frame format before (or after) opening:

  • Pixel format — GenICam pixel format string (see Pixel Formats).
  • Width / Height — sensor dimensions in pixels. Default: 5328 × 4608 (ATX245 full sensor).
  • Re-parse — re-reads the file with the current settings without a file dialog.

💡 If a JSON sidecar or a filename containing the format string (e.g. capture_Mono12p.raw) is detected, the viewer fills in Pixel format and dimensions automatically.

Sidecar JSON Metadata

Place a .json file alongside your data file to pre-populate the viewer. The viewer searches for (in order):

  1. <datafile>.json — e.g. capture.raw.json
  2. <stem>.json — e.g. capture.json
  3. metadata.json in the same directory

Supported keys:

{
  "width":            5328,
  "height":           4608,
  "pixel_format":     "Mono12p",
  "fps":              30.0,
  "acquisition_time": "2025-06-01 09:14:32",
  "notes":            "Dark-field calibration run"
}

✔ Both pixel_format (new) and pixelformat (legacy) keys are accepted. Encoding is auto-detected: UTF-8 BOM, UTF-16, and Latin-1 are all handled.

Timestamps CSV

If a timestamps.csv file is found in the same directory as the opened data file, frame timestamps are shown in the frame label beneath the image.

CSV format

  • One row per frame (header row optional).
  • The timestamp column is auto-detected — columns with sequential integer steps (frame index) are skipped.
  • Header names timestamp, time, ts, ticks, system, device, or t (substring match) take priority.
  • Units are auto-scaled: absolute epoch values are converted to relative seconds; display unit is chosen from ms / s / min based on the total span.

Column header suffix hints (e.g. device_ts_ns, _us, _ms) are used for pre-scaling before the automatic unit detection runs.

frame,device_ts_ns,system_ts_us
0,1717000000000000,1717000000000
1,1717033333333,1717033333
...

Levels

Use the pyqtgraph histogram on the right to drag the level handles manually, or click Auto levels in the sidebar to fit the display range to the current frame's actual min/max.

Levels are set automatically on the first frame of each new file, then held fixed while scrubbing — this prevents flickering during playback.

Field Correction & Transmission

The Correction panel in the sidebar applies flat-field correction using reference frames captured under known illumination:

  • Dark field — finds the most recent dark_field_* folder in the parent directory and averages all of its frames as the dark reference.
  • White field — finds the most recent white_field_* folder and averages all of its frames as the white (flood) reference.

When both references are loaded, each pixel is converted to x-ray transmission:

transmission = (data - dark) / (white - dark)

With only one reference loaded the viewer falls back to data / white (white only) or data - dark (dark only). Per-frame camera gain (from frame_data.csv) is automatically compensated when the references were captured at a different gain.

💡 The displayed image now shows the true float transmission value, not a rescaled integer. Click any pixel with the inspector to read its transmission directly (e.g. [x, y, 0.8423]). Transmission is typically ≈0 (fully absorbing) to ≈1 (fully transmitting), and can slightly exceed that range due to noise.

⚠ If the open file already has correction baked in (its filename contains _dark or _white), both correction checkboxes and the pixel mask are disabled — applying either step again would be incorrect.

TIFF Export

Use File → Export TIFF stack… (Ctrl+E) to write the current stack to a multi-page TIFF. Acquisition metadata (source file, pixel format, dimensions, FPS, timestamps, gains, exposures, line status, and the active correction) is embedded in the TIFF.

Transmission encoding & the decode key

To keep hundreds of frames from ballooning in size, corrected frames are stored as integer codes (e.g. 12-bit, 0–4095) rather than raw floats. So the float transmission can be fully recovered, each frame is mapped with its own per-frame minimum and maximum transmission — computed during the single write pass, so there is no slow pre-analysis step. Every frame therefore uses the full code range, and the per-frame min/max are recorded so the mapping is reversible.

In the standard (non-ImageJ) TIFF, each page carries its own values in its ImageDescription, and page 0 also records the decode convention in the correction block:

// page 0 ImageDescription
"correction": {
  "formula":  "transmission = (data - dark) / (white - dark)",
  "code_max": 4095,
  "decode":   "per frame i: transmission = code / code_max * (transmission_max[i] - transmission_min[i]) + transmission_min[i]",
  "note":     "transmission_min/transmission_max are stored per page in each frame."
}
// every page (including page 0)
{ "frame_index": 7, "transmission_min": -0.0123, "transmission_max": 0.9876, "code_max": 4095 }

To recover physical transmission for a pixel in frame i, read that page's own transmission_min/transmission_max:

transmission = code / code_max * (transmission_max - transmission_min) + transmission_min

✔ The round-trip is reversible to within one code step ((transmission_max − transmission_min) / code_max). Because each frame is scaled independently, compare absolute transmission between frames only after applying each frame's own min/max.

⚠ In ImageJ-compatible mode the TIFF is written in the exact layout ImageJ expects (no embedded extras), so the per-frame conversion factors are written to a JSON sidecar named <name>_transmission.json next to the file instead. It contains transmission_min and transmission_max arrays (indexed by frame number) plus code_max and the decode formula. Per-frame timestamp metadata is also not written in this mode.

// <name>_transmission.json
{
  "transmission_min": [-0.0123, -0.0098, ...],
  "transmission_max": [ 0.9876,  0.9912, ...],
  "code_max": 4095,
  "decode": "per frame i: transmission = code / code_max * (transmission_max[i] - transmission_min[i]) + transmission_min[i]"
}

Large files (> 4 GB) & BigTIFF

Standard exports automatically switch to BigTIFF once the stack exceeds 4 GB, so there is no size ceiling. The ImageJ-compatible format, however, is hard-capped at 4 GB and cannot be BigTIFF — an ImageJ-format file larger than that will not open.

✔ If you request ImageJ mode for a stack larger than 4 GB, the viewer automatically falls back to a standard BigTIFF (which ImageJ/Fiji opens via Bio-Formats) and tells you it did so. In that case the per-frame transmission factors are embedded per page in the TIFF, so no sidecar is produced.

Tools Menu

Launches the Lucid Viewer batch script (lucid_viewer.bat) using Windows ShellExecute. This opens the associated camera-control or acquisition tool in a separate process; the viewer application continues running normally.

Troubleshooting

SymptomLikely cause & fix
No complete frames fit in file Width × Height or pixel format is wrong. Verify against the acquisition settings and click Re-parse.
Image looks scrambled / noise-like Packed format mismatch (e.g. Mono12p vs Mono12Packed). Try the other variant.
TIFF / MP4 import fails tifffile / zarr or opencv-python not installed. Run: pip install tifffile zarr opencv-python
Colormap not found CET maps require colorcet: pip install colorcet
Timestamps ignored The CSV must be named exactly timestamps.csv and be in the same folder as the data file.
